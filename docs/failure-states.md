# Failure states

Every data skill carries the rules block from `shared-rules.md`. This table is the reference behind it: how each state is detected, what causes it, what the user reads and what the skill must not do. Detection strings are the exact texts the Greenhouse MCP server and Harvest return.

| # | State | Detection | Cause | What the skill does | Must not |
|---|---|---|---|---|---|
| S0 | Not connected | No Greenhouse tool in the session's tool list | Connector never added, or not connected on this surface; on a team or enterprise plan the workspace owner has not added it | Stop before any call. Print the per-surface connect text (the app's plugin or connector settings in a desktop or web app, or the MCP command in a command-line client) and the non-admin sign-in note | Invent data, ask clarifying questions, try other tools |
| S1 | Hidden tool | A tool the skill wants is absent while other Greenhouse tools are listed | The org's MCP Access ceiling excludes the scope, or the user left it unticked at consent | Skip the section it feeds, finish everything else, one footnote naming the sections and the scope keys, point to `/greenhouse:configure`. The skills named for an enhancement degrade the same way: `interview-week` without `list_interviews` runs on the default tools and shows scorecards started but not submitted, headline "I can't see interview times with your current access; n scorecards from the last 30 days are started and not submitted"; `source-review` without `list_sources` gives the totals and the referrer line, "source names are not visible with your access" | Call the tool anyway (it will be declined); say "not connected"; stop, or make no call, because an enhancement is missing |
| S2 | Denied call | Result text begins `Permission denied.` The current Greenhouse MCP server adds a sentence saying which: `This connection is missing the scope(s) ... Reconnect and select them. If they aren't offered, ask a Greenhouse admin for that permission first.` (the token lacks the scope), `Your Greenhouse account doesn't have permission to perform this action. Ask a Greenhouse admin if you need access.` (the user's own permission or role on that req), or, for a tool with no declared scopes, `Your token does not have the required permissions for this operation. Please reauthorize with the correct permissions.`; each is followed by ` Harvest said: <detail>` when Harvest returned a JSON reason, which Greenhouse's own 403 responses always carry. An earlier wording of the same error, `Permission denied. Your token is missing the scope(s) required by this tool: ...`, covers every 403 | A Harvest 403: a missing scope (stale tool list, unticked at consent, outside the ceiling), the user's own Greenhouse permission (private candidates, salary and private fields, admin-only data), or a product the org lacks (Talent Matching, Real Talent) | Say once that Greenhouse declined the tool and which fix applies (reconnect and tick, or ask a Greenhouse admin); continue without that data | Repeat "reauthorize"; retry |
| S2b | Consent empty | `configure`'s probe call returns S2 text | The token carries no Harvest data scopes | `configure` only: tell the user to disconnect, reconnect and tick the data categories they need; stop | Run skills on an unusable connection |
| S3 | Empty result | `{"data": []}` or `[]` from `get_job` | None exist, the user cannot see them, or the filter is wrong. `get_job` returns `[]` for an invisible id; `list_offers` returns `[]` without the private-data permission | Say which causes are possible ("not found or not visible to you", "no offers, or you don't have the private and salary data permission"). An empty "mine" scope: say so and ask how to scope | Widen to org-wide data on its own; invent records |
| S4 | Revoked or disabled token | Result text contains `HTTP 401`, `Token has already been refreshed or revoked`, `User is unknown or disabled`, or `Organization is disabled` | A Site Admin changed the MCP Access scopes (every org token is invalidated), your organization's MCP access changed, or the user was disabled. The error arrives as a tool result, so the client does not refresh on its own | No further Greenhouse calls this turn. Per-surface disconnect-and-reconnect text | Retry; continue with other calls |
| S5 | Rate limited | `Harvest API returned an error (HTTP 429)` as tool-result text, or an HTTP 429 from the MCP server itself (body `Rate limit exceeded. Try again later.`), which the client reports as a transport error rather than a tool result | Greenhouse rate-limits requests; the limit is shared with your organization's other custom Harvest integrations | Stop fanning out, deliver what is already loaded, mark missing sections "rate-limited; re-run in a minute"; at most one retry with a smaller `per_page` | Loop, sleep-retry, re-send identical calls |
| S6 | Argument or unexpected error | `An unexpected error occurred. Please try again.`, `Invalid arguments:`, `Missing required arguments:` | An argument the tool does not accept (`parent`, `note_type`, a non-numeric string where an integer id is required, more than 50 ids, two bounds on one side of a date range); also a slow upstream response. A `cursor` sent with other arguments does not fail: the other arguments are silently dropped | Correct the call once from the message; if it fails again, report the section unavailable. After a write, read the record back before any retry | Re-send blindly; add arguments the tool schema does not list |
| S7 | Other Harvest error | `Harvest API rejected the request (HTTP 4xx): <message>; <errors>` or `Harvest API returned an error (HTTP 5xx). Please try again or contact support.` | Wrong or stale id (404, 422 `Couldn't find Candidate`), a stale stage on a move (422 `This application is not currently on this stage.`), or an upstream outage | Quote the text for that section and continue. On the stale-stage 422, re-read the application and re-preview | Guess ids; retry a write without reading back |
| S8 | Non-admin cannot authorize | The Greenhouse sign-in page says `Only organization administrators can authorize MCP applications.` | Non-admin MCP authorization is off for the organization; Greenhouse's account team enables it, a Site Admin cannot. Rule 0's text names a Site Admin; README and SETUP name the account team | A skill never sees this. README and SETUP document it; `configure`'s S0 text mentions it | |
| S9 | Connector mismatch | Two Greenhouse connectors in the account: the plugin's `https://mcp.greenhouse.io/mcp` and another connector entry for the same server (`mcp.us.greenhouse.io`) | Two connectors with different URLs show duplicate tools | `configure` only suggests a connector directory entry whose URL equals the plugin's; otherwise prints rule 0's text, which points to the app's plugin or connector settings. With both listed it uses this plugin's tools and says once that the other duplicates it | Suggest the other entry; ask the user to choose |

## When reconnecting does not help

Token scopes = scopes the user ticked at consent, intersected with the org ceiling, intersected with the scopes the user's role may grant. Reconnecting changes only the first factor. The current server tells the two cases apart: a scope the token lacks ("This connection is missing the scope(s)") is fixed by reconnecting and ticking it, or by a Site Admin adding it to the ceiling first; a Harvest permission denial ("Your Greenhouse account doesn't have permission") is the user's own Greenhouse permission or role, and reconnecting cannot help. The skills quote the fix that matches and never repeat "reauthorize" on its own.

## Scope keys the skills can name

Default ceiling: `harvest:applications:list`, `harvest:candidates:list`, `harvest:job_interview_stages:list`, `harvest:jobs:list`, `harvest:rejection_reasons:list`, `harvest:scorecards:list`, `harvest:users:list`.

Enhancements and writes: `harvest:interviews:list`, `harvest:interviewers:list`, `harvest:application_stages:list`, `harvest:offers:list` (plus the user's private-data permission), `harvest:openings:list`, `harvest:notes:list`, `harvest:notes:create`, `harvest:applications:move`, `harvest:job_hiring_managers:list`, `harvest:job_owners:list` (named by `configure` only; no data skill reads `list_job_owners`), `harvest:scorecard_candidate_attributes:list`, `harvest:ai_opt_out_statuses:list` (plus Talent Matching), `harvest:sources:list`, `harvest:interview_kits:list`, `harvest:job_interviews:list`, `harvest:scorecard_questions:list`, `harvest:scorecards:create`. `whoami` has no scope key: it is a tool of the MCP server, listed on every connection where the server enables it, so no footnote names it and MCP Access cannot switch it on or off.

Changing the ceiling: Configure > Dev Center > MCP Access > Endpoints. The confirm dialog reads "Saving any change will require existing MCP connections in your organization to reconnect and reauthorize." Clients may keep the old tool list for a few minutes, so a change can take that long to show in a conversation.
